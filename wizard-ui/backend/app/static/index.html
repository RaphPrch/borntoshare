Comment installer BornToShare ?

Les bases restent sur votre MariaDB dans les trois cas. Ce qui change : où tournent les services, et qui publie l’interface web.

B Installateur BornToShare — Étape 1 : Préparer 1 · Préparer2 · Déployer
Étape 1 · Préparer

    Prérequis

    Lus sur ce serveur par make wizard (). Un point rouge bloque la suite ; un orange se règle pendant le déploiement.

    L’interface web sera publiée par httpd
    Après une correction sur le serveur : make wizard-check, puis Relire.

    Serveur MariaDB

    Un compte qui peut créer des bases et des comptes (root, en général). Il sert à cette installation seulement, jamais écrit.

    Certificat et nom du serveur vérifiés : autorité capsule-runner/certs/db-ca.pem, sinon celles du système. Vaut pour tous les services.
    Obligatoire pour continuer.

    Bases et comptes SQL

    Chaque usage a son compte, avec le minimum de droits ; les mots de passe sont générés et ne sont jamais affichés.

    CompteDroitsSon mot de passe
    lecture et écriture sur ; ajout, lecture et purge sur
    schéma et données, sur toutes les bases (installateur, mises à jour)

    Une base déjà présente est conservée ; un compte qui existe reçoit un nouveau mot de passe et exactement ces droits.

    Accès à l’interface

    Le conteneur de l’interface est publié sur un port de ce serveur. L’adresse publique est celle que les utilisateurs taperont : elle sert aux liens des e-mails et à la protection des formulaires.

    Un reverse proxy de l’entreprise (F5, HAProxy, httpd existant) peut se placer devant ce port : l’adresse publique est alors la sienne. Pour que BornToShare le publie lui-même avec httpd, choisissez le mode Hybride.

    Interface web (httpd)

    L’interface tourne en service Node.js, sur 127.0.0.1:3000 ; Apache httpd la publie en HTTPS sous votre nom, avec votre certificat.

    Sur quel serveur ?
    Écrit dans /etc/httpd/conf.d/borntoshare.conf

            Installer l’interface sur le serveur annexe
            
            
    
              
              
            
    
            Clé seulement, jamais de mot de passe. Le déploiement copie l’interface, installe son service, le vhost et la règle SELinux sur l’annexe, puis vérifie qu’elle joint ce serveur.
            Le déploiement prépare dist/borntoshare-web.tar.gz : à copier sur l’annexe, puis sudo borntoshare-web/install-web.sh. Il contient le jeton des services (fichier 0600) : à transférer par un canal sûr, puis à supprimer.

    Choisir au moins la gouvernance ou le 5S.
    
          
    5S seul : BornToShare lit l’annuaire et les serveurs, sans rien y créer. Les demandes d’accès restent masquées.
    
          
    
            
            
    Vérifiée ici, sans connexion : rien ne sort de ce serveur.
    
            
    
            
    
              
              
              
            
    
            
    
              
              
    
                
    L’inventaire grossit avec le nombre de fichiers : un serveur à part ne pèse pas sur la gouvernance. Le compte de migration y est créé aussi ; TLS comme le premier serveur.

    Messagerie (SMTP)
    Les e-mails de BornToShare : demandes à valider pour les gardiens, décisions, fins d’accès, revues. Repris dans Réglages avancés › Notifications.
    
          
    
            
            
            
            
            
            
          
    
          
    
          
    
          
    Le mot de passe est chiffré par BornToShare au premier démarrage, avec sa clé ; d’ici là il attend dans secrets/ (0600), jamais dans .env.
