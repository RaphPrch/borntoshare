Les mots de passe restent dans cette page le temps de l'installation : rien n'est enregistré, ni écrit dans un fichier.

Étape 1 sur 5

Serveur MariaDB

Un compte qui peut créer des bases et des comptes (root, en général). Il sert à cette installation seulement.

Étape 2 sur 5

Bases BornToShare

La base des données de l'application et celle de son journal d'audit, sur ce serveur, avec un même compte SQL.

    Si le compte existe déjà, il prend ce mot de passe : c'est celui de DB_PASSWORD dans .env.

    Étape 3 sur 5

    Administrateur

    Le premier compte local, administrateur de la plateforme. Il ouvre l'assistant de premier lancement (annuaire, serveurs, dossiers).

      Étape 4 sur 5

      Licence et modules

      Une clé de licence ouvre les modules optionnels. Sans clé, BornToShare s'installe sans eux : la clé pourra être ajoutée plus tard dans Réglages avancés › Fonctionnalités.

      Vérifiée ici, sans connexion : rien ne sort de ce serveur.
        Étape 5 sur 5

        Prêt à installer

        Vérifier, puis installer. Une base déjà présente est conservée : rien n'est effacé, les paquets SQL s'appliquent à nouveau.

          À reporter dans .env

          Puis arrêter ce wizard et démarrer BornToShare. Le bouton copie les lignes avec les mots de passe saisis ; l'écran les masque.

          
          
          
          
          make wizard-down
make deploy
          
          
          Ensuite, se connecter avec le compte  : l'assistant de premier lancement prend le relais.
